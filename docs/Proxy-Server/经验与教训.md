一开始我是一个 Vultr 的 VPS

根据连接它的电脑的物理位置和运营商，有的好，有的坏，反正大概率能用

家里的那个电脑，连接 VPS，因为我用 VLESS 协议，它 TCP 握手总是失败，一直都很卡

有一天，我升级到 Hy2，那时候确实爽，视频随意看，问题是过了两周就被识别到了，整个 VPS 的回程 UDP 被阻断（所有端口），只能继续回到 VLESS

然后情况开始恶化（也许是和现实事件有关），TCP 的可用性也越来越差，没死，但是半死不活

让 AI 检查了一番，一个是跑多网络多机的抵达性测试，一个是继续注册多个 VPS，跑脚本选优。弄了一个新的 VPS，一开始还不错，结果过一阵子马上就开始继续坏

结论是

（1）我的家庭出口是电信，走了“163 骨干网”，在那边被卡住了。我换协议，只能提高伪装性，但是无法提高链路可用度

（2）因为是多机，运营商出口不同，如果我不想走骨干网，我必须找三网优化的服务器，不能找单一运营商优化的（比如只有 CN2 GIA）

（3）家庭宽带，除非是对面买了 IP 段，并且放到服务器上，不然大概率走骨干网，依旧卡。你买 AWS Azure 一样卡，都走骨干网

结论就是，你得买专线。至于你要买什么，和本文无关。

然后几个教训是：

你最好买那种，在国内 IP 就能直连其网页的机房。否则你又遇到鸡生蛋、蛋生鸡的问题。

你的邮箱，一定要走 outlook，而不是 gmail。因为你的 VPS 一旦挂了，你想继续登陆 VPS 提供商，你 IP 必然变（你走备用机场，走国内直连都会变），一旦变 IP，VPS 提供商就出触发风控，要求验证邮箱验证码，而你 google 还得再重新开梯子进去，google 依旧遇到这个问题，你 IP 变了，要求你验证手机号，简直。再叠加备用机场的烂 IP，你一辈子过不去 cloudflare 的风控了。

第二个，你的部署脚本、所有套件，必须有国内 AI（harness + AI）兜底，比如 dsh + deepseek。因为你一旦梯子死了，你的 gpt gemini 全跟着无法访问，你必须让国内 AI 来解决问题。

第三个，环境变量管理对。既然 VPS 坏了，就把 v2ray 切到“清除系统代理”，要么就是把环境变量清理掉。不要没代理进程硬走，或者走不通。和 AI 对话时，也告诉它现状，加快解决速度，否则它偶尔可能会忽视，尤其是测下一个 VPS 联通性的时候

第四个，如果不着急，可以开手机热点最终兜底
