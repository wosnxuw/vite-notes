# 从机器学习到 Agent：先验、信息边界与如何管理现在的 AI

这篇文章试图跳出具体模型的调参细节，从机器学习最底层的“函数拟合与信息边界”出发，一路推演到今天的预训练大模型与 Agent 架构，最后回答一个工程上最现实的问题：**当底层模型的权重被大厂冻结且垄断时，我们在外围写 Harness、做垂直应用、管理 AI，究竟在做一件什么事？**

---

## 一、机器学习的起点：寻找函数 $f(X)$ 与它的天然边界

站在最高层看，传统监督学习只做一件事：给定输入特征 $X$（比如房子的面积、地段、学区、楼龄），让机器从历史数据里自动找一个函数 $f$，使得预测值 $f(X)$ 尽可能逼近真实结果 $y$（房价）。

在挑选任何模型架构之前，有两个底层问题直接划定了机器学习的能力边界。

### 1. 输入里没有的“隐藏参数”，模型能学到吗？

真实世界的公式往往是 $y = f(X) + \epsilon$。如果有一个没写进表格的隐藏因素 $Z$（比如房子临街“噪音大”），模型能不能学到，完全取决于 $Z$ 和已有输入 $X$ 之间有没有统计关联：

- **如果强相关，能间接“蹭”到**：比如数据里没写噪音，但记录了“市中心 + 低楼层”。模型根本不知道“噪音”这个概念，但它算账时发现符合这个组合的房子普遍便宜 30 万，就会自动把这 -30 万的惩罚揉进对应的权重或切分规则里。
- **如果完全独立，数学上绝对学不到**：两套房子的输入 $X$ 一模一样，但 A 房楼下恰好有个表里没记录的违建夜宵摊，卖 450 万，B 房卖 500 万。不管是树模型还是千亿参数大模型，面对同一个输入 $X$ 只能映射出同一个确定输出，最终只能被迫输出折中平均值（475 万）。

这部分因为信息缺失而永远无法消除的误差，就是**不可约误差（贝叶斯误差 $\epsilon$）**。模型架构只能逼近现有特征 $X$ 所包含的信息上限；特征里压根没有的独立信息，换神仙架构也算不出来，只能靠加数据（特征工程或扩大感知范围）解决。

### 2. 既然要“一股脑自动学习”，为什么还要人来挑架构？

如果表格里有 200 列特征，人类肉眼根本看不出“第 47 列和第 182 列同时大于某个数时会发生化学反应（特征交互）”，所以才要把数据一股脑扔给机器自动搜。

但“自动搜”不能是无约束的乱搜。能精确穿过有限几个已知样本点的函数有无穷多个（可以是直线、阶梯、剧烈震荡的高次多项式，甚至是死记硬背的查表函数）。如果不加限制，有限的数据根本锁不住解，必然严重过拟合。

因此，在训练开始前，人必须先给机器硬编码一套“先验偏见”——规定允许它用什么形状的几何积木去组合特征。这就是**归纳偏置（Inductive Bias）**。

## 二、归纳偏置的光谱：从强约束到大力出奇迹

以前学机器学习时很容易陷入一个误区：觉得线性模型是石器时代，树模型是工业革命，深度神经网络才是现代文明。一上手就默认选深度神经网络，效果不好就加减层、调参数，最后归咎于“数据少、过拟合”。

如果退后一步，把所有架构放进“归纳偏置”的地图里横向对齐，就会发现传统架构从来没有“过时”，它们只是针对不同数据物理质地的特化积木。

### 1. 强偏置与弱偏置的几何直觉

以最经典的决策树（如 LightGBM / 随机森林）和深度神经网络为例。

一棵决策树本质上就是一段自动生成的嵌套 `if-else` 代码（随机森林是找 100 棵树并行估全价取平均；GBDT/LightGBM 是找 100 棵树串行接力，后一棵树专门拟合前面所有树累加后的残差补丁）。在几何上，树每次分裂只看一个特征，只能**横平竖直地切格子**。
这种强偏置天生克制表格数据：现实表格每一列都有独立物理含义，充满硬阈值和断崖跳变（如满 90㎡ 契税跳档），而且哪怕塞进 150 列毫无意义的垃圾特征，树在算分裂增益时发现没用就会直接无视。但它的短板同样明显：如果真实规律是一条斜线（比如 `收入 - 负债 > 10万`），树只能用无数个小台阶去锯齿状逼近，且叶子输出是历史样本的平均，永远无法向训练集范围之外做趋势外推。

深度神经网络则完全相反。每个神经元一上来就把所有特征乘权重加在一起（$w_1x_1 + w_2x_2 + \dots$），再过激活函数折弯。在几何上，它可以**以任意角度捏出平滑曲面**，并在隐藏层里把原始信号压缩成低维连续的抽象向量（表征学习）。
这种弱偏置在面对图像像素、音频、文本或千万级离散 ID 时是唯一解——因为单个像素或单词没有独立含义，必须靠全局斜向组合。但拿它去啃中小规模的干净表格，它的“平滑偏置”去拟合硬阶梯会非常别扭，且所有输入混在一个点积公式里，数据量不够大时根本压不住垃圾特征的噪声权重。

### 2. 架构演进的光谱与《苦涩的教训》

把视野拉大，整个架构演进史其实是一条**归纳偏置从“极强”走向“极弱”的光谱**：

- **线性模型**：偏置极强，强行假设特征之间互不干扰、变化率恒定（画直线/平面）。
- **树模型**：假设轴对齐局部性与特征稀疏（横平竖直切方块）。
- **CNN（卷积网络）**：针对图像注入“空间局部性 + 平移不变性”（猫在左上角和右下角是同一只猫）。
- **RNN / LSTM**：针对序列注入“时序单向递推”（越近的历史影响越大）。
- **GNN（图网络）**：针对图谱注入“邻居拓扑关系”。
- **Transformer**：**极弱的结构偏置**。它不预设局部性，也不做串行递推，默认任意两个元素都可能直接相关（全局自注意力）。

做架构选型，本质上是在做**样本效率**与**能力上限**的权衡。强偏置把搜索空间大幅剪枝，几千条数据就能学得又快又准，但一旦真实规律违背假设，上限就被锁死；弱偏置几乎不设限，上限极高，但搜索空间过于庞大，需要海量数据交齐“克服几何偏置的学费”。

这就是 Sutton 在《苦涩的教训》（The Bitter Lesson）里指出的规律：短期内，往系统里塞入人类总结的强偏置和精巧特征往往见效最快；但长期来看，只要算力和数据量跨过临界点，偏置更弱、更通用的架构（如 Transformer）靠大规模搜索与学习，最终会碾压强偏置设计。

当然，这并不意味着 Transformer 已经一统天下。在原本老架构就能正常干活的领域里，版图依然极度分化：它彻底清场了依赖串行递推的传统 NLP，并通过 DiT 全面接管了大规模视觉生成；但在端侧实时视觉检测（CNN）、工业大图计算（GNN）、低维高噪的传统数值时序（GBDT/线性层）以及毫秒级高频物理控制（MLP）中，老架构靠着精准的归纳偏置和极高的计算密度，至今依然是主力。

## 三、信息守恒：从“小样本防过拟合”到“AI 左脚踩右脚（RSI）”

理解了模型只是在特定偏置下做信息拟合，就能看清机器学习里一条铁律：**数据处理不等式（信息守恒）**。

### 1. 为什么“靠小样本自己造数据”是死胡同？

在样本有限的领域，很多人试图写脚本随机生成数据、重采样，或者用小样本训一个生成模型再吐出 100 万条假数据来喂给模型。

从信息论看，对同一份有限样本，无论怎么重采样或内部倒腾，样本里的有效信息总量一比特都不会增加。一旦走上这条路，模型的上限就彻底锁死在了“数据生成器”的粗糙边界里——练得越努力，只是把生成器的偏见背得越牢（大模型用 AI 合成数据反复自训导致的“模型崩溃 Model Collapse”，底层也是同一个死结）。

在样本有限时，真正不自欺欺人的解法只有两条路（本质上都是在遵守信息守恒）：
1. **向外部借真值信息**：要么用外部海量数据预训练好的底座做迁移学习（冻住 99% 的层，只用小样本锁死最后几百个参数）；要么在数据增强中注入 100% 确知的物理对称性（如“芯片裂纹旋转 90 度依然是裂纹”）；要么接入装有真实物理方程或明确规则的仿真器（如自动驾驶物理渲染、AlphaZero 的围棋规则）。
2. **狠心阉割模型自由度**：退回带强正则的线性模型或浅层树，把人类领域知识直接算成显式特征（比如知道断裂取决于“压力/截面积”，就直接喂比值，别指望模型从 100 行数据里自己摸索出除法），并严守验证纪律（按实体分组切分防泄漏，警惕工程师反复调参导致“人脑对验证集过拟合”）。

### 2. 现在大厂谈的 RSI（递归自我改进），打破信息守恒了吗？

既然封闭系统不能左脚踩右脚上天，为什么 Anthropic 等前沿实验室又在谈 RSI，声称“AI 自己训练自己、在智力提升中贡献越来越大”？

因为他们说的根本不是“关在黑屋子里自己生数据自己学”的封闭自举，而是把系统变成了**开放回路：用算力去向外部真实世界“套取”新信息**。

支撑这套循环的物理引擎，是计算机科学里一个深刻的不对称性：**生成与验证的不对称性（Generator-Verifier Gap）**——很多问题“想出解法”极难，但“验证解法对不对”极容易且 100% 客观。

比如写一段把矩阵乘法提速 50 倍的底层 GPU 内核代码，人类可能想破头也写不出来；但只要把 AI 盲猜出的 1000 个代码方案扔进真实的编译器和 GPU 集群里跑一遍，报不报错、耗时降了多少，物理世界会在几秒钟内给出绝对客观的真值反馈。把跑得最快的那个成功路径筛出来、固化进下一代模型权重，本质上就是**把算力（Compute）兑换成了来自外部物理与数学世界的新信息**。

这里有一个极其关键的**能力门槛（相变点）**：
如果模型太弱，提交 1000 次代码全编译报错，外部奖励信号永远是 0，飞轮根本转不起来。海量静态数据集预训练并没有打破信息论，它起到的是**“点火器”**的作用——把人类的代码语法、常识和逻辑压缩进权重，让模型跨过“能提出大概率合法的猜想”的起跳门槛；跨过门槛后，再撤掉人类的标准答案，接上客观验证器，靠算力试错去突破人类示范的天花板。

这也直接决定了 RSI 撞墙的硬边界——**验证器瓶颈（Verifier Bottleneck）**：
凡是有客观、廉价、高频外部验证器的领域（软件工程、数学形式化证明、算子优化、芯片仿真），AI 就能靠算力换信息飞速进化；一旦进入没有客观裁判或验证极慢极贵的领域（如医药临床试验、复杂价值判断、审美），外部信息注入断崖下跌，如果硬用“AI 给 AI 当裁判”，系统就会退化回封闭回路，要么模型崩溃，要么演化出专门钻裁判漏洞的 Reward Hacking（古德哈特定律）。

## 四、范式转移的真实案例：为什么当年的 3D 逆向建模必败，今天却成了？

顺着“预训练点火 + 外部验证器闭环”的逻辑回头看，很多当年用传统深度学习死活啃不下来的工程难题，死因和今天的解法一下就全通了。

一个“逆向 CAD 建模”的课题：试图训练一个网络，看一眼最终的 3D 拓扑模型成品，就能直接逆向还原出它的建模步骤树（拉伸、倒角、布尔运算等，不是纯三角网格）。当时几乎踩遍了所有坑，最后不了了之；但多年后，依靠多模态 LLM 看图 + 写建模代码 + 多轮渲染迭代，它反而走通了。

用现在的视角复盘，当年的设想撞上了传统监督学习的三个结构性死穴：

1. **一对多逆问题导致“多峰目标坍缩”**：同一个带通孔的方块，既可以“先拉伸方块再布尔打孔”，也可以“先画带孔草图再一次拉伸”，结果完全等价。当时为了解决路径不唯一，我特意把多种合法画法都塞进训练集，指望模型学得更丰富。结果在监督学习框架下，同一个输入对应两个截然不同的标准答案，样本 A 的梯度强迫第一步输出“实心拉伸”，样本 B 的梯度强迫输出“空心草图”。梯度互相打架，模型为了最小化平均误差，要么学出几何内核直接报错的“折中缝合怪”，要么死记硬背极其微小的噪声去强行区分该用哪种画法（严重过拟合）。
2. **验证器设错了位置**：当时损失函数核对的是“预测的步骤序列和标准答案像不像”。这就像修 Bug 时拿正则表达式去校验新代码字符串一样荒谬——过程不唯一，核对过程本身就是错的。
3. **自己造数据撞上分布鸿沟与组合爆炸**：用脚本随机拼装拉伸、打孔生成的几万条数据，全是“合法但无意义”的几何体，根本覆盖不到真实工业零件里对称、壁厚均匀、装配对齐的设计意图。

而今天的“多模态 LLM + 写代码 + 多轮迭代”之所以能成，是因为它彻底改写了求解范式：
- **从“小样本从零学几何”变成“外部借力”**：大模型在预训练阶段已经吃透了代码语法与三维空间常识，跳过了冷启动死局。
- **验证器从“核对步骤”换成了“核对执行结果”**：模型写出的建模脚本直接扔进 CAD 几何内核与渲染器。几何内核做第一道硬验证（拓扑是否合法、报不报错）；多视角渲染图与目标对比做第二道视觉验证（只看长出来的成品像不像，彻底不管你是先打孔还是先拉伸）。“一对多”的死结瞬间消失。
- **从“开环盲猜”变成“闭环反馈控制”**：不要求模型看一眼就一次性背出 30 步精确参数，而是允许它先画个粗胚 $\rightarrow$ 渲染看一眼哪里少个槽、哪个圆角太大 $\rightarrow$ 照着视觉残差改代码重跑。把极难的单步逆推，降维成了高容错的闭环纠错。

## 五、如何看待与管理现在的 AI：权重冻结时代的工程位置

搞清楚了从“静态函数拟合”到“动态验证器闭环”的演进，我们终于可以落到最现实的问题上：

今天，全世界只有极少数大厂有资源训练基础大模型，绝大多数开发者拿到的只是一个**权重完全冻结的黑盒（或虽开源但改不动参数的庞然大物）**。我们每天在 GitHub 上研究各种 Coding Harness（如 Codex、Claude Code、Pi、OpenCode），或者在垂直领域做 Agent 应用、维护自己的 Skill 库。

当模型权重已经冻住时，我们在外围做的这一切，究竟只是在画随时会被下一代模型吞掉的“临时补丁”，还是在构建真正有价值的东西？

### 1. 为什么看开源 Harness 仓库，永远只能做“马后炮”？

很多人习惯拉取 Codex 或各类开源 Harness 的代码，逐行拆解它的提示词、工具定义和架构演进，试图从中推演 Coding Agent 的下一步大方向，却发现网上的分析永远只是事后诸葛亮。

因为拉开源代码猜未来，本质上是在**“看壳猜肉”**。卡住外部观察者的有三个盲区：
- **壳与肉的联合训练（你在适配今天的模型，厂家在适配明天的模型）**：外人以为 Harness 是单向迁就黑盒 API 的胶水代码；但大厂的第一方工具（如 Codex、Claude Code）与底层模型是双向联合演化的。厂家在用强化学习（RLVR）训练下一代模型时，模型就是直接插在内部新版 Harness 里练出来的。当你看到某次提交突然砍掉了复杂的 AST 索引工具、改用极简的 `rg/grep`，或者换了某种 diff 格式，往往不是工程师突然悟出了绝妙的软件架构，而是内部模型检查点在这个极简接口上跑出了更高的分数，把旧设计直接掀翻了。
- **传统软件做加法，Harness 演进一半在做“减法”**：传统软件架构是可预测的加法（抽象越来越厚、模块越来越完备）。但 Agent Harness 里有一大半代码本质上是**认知拐杖（Scaffolding）**——为了弥补当前模型长上下文遗忘、规划弱、改长文件易出错而硬写的补丁。一旦底层模型智力跨过某个门槛，最优演进不是升级拐杖，而是**把拐杖折断扔掉**。这也是为什么像 Pi 这类第三方工具会有意识地走极简路线：不和模型抢脑子，把核心循环削到极薄，就是为了主动规避“脚手架腐烂”，顺势吃满所有厂商模型升级的红利。
- **开源的是“答案”，藏起来的是“千万级失败遥测”**：你看得到某次 commit 的最终代码，但看不到第一方后台每天几百万条真实轨迹绘出的“故障热力图”（哪类工具最容易卡死、超过多少 Token 指令遵循率断崖下跌、子 Agent 拆到多细时沟通损耗大于收益）。没有失败分布，自然看不出排在第一位的真实阻塞点。

### 2. 区分两类“框”：什么是认知拐杖，什么是真壁垒？

既然第一方在“压榨单模型极限智商”上有天然优势，且复杂的认知脚手架随时会被新模型淘汰，那我们在垂直领域给 AI 加一个“更紧的框”，还有没有意义？

关键在于**你框住的究竟是什么**。工程上必须把外围的“框”严格切成两类，它们的宿命完全相反：

**第一类框：认知拐杖（框住模型“怎么想”）**
比如硬编码死板的 SOP 状态机、模仿人类组织架构搞一堆 PM/Coder/Reviewer 角色互相聊天、写几千字提示词教模型每一步按什么顺序推理、或者针对**单次回答错误**不断往提示词里打地鼠式地塞规则补丁。

这类框的本质，是**在推理期向模型强行注入“人工强归纳偏置”**——替当前不够聪明的模型“代劳思考”。
必须承认：**认知拐杖在当下绝不是“完全没用”的**。恰恰相反，正如第二章里强偏置的树模型在小样本下见效最快一样，在当前这一代模型身上，一套写死的排查路径或详细提示词，往往能立刻把原本要盲搜 40 轮的慢过程压到 10 轮以内，也能强行拉齐不同“模型脾气”（比如有的模型倾向于写几行脚本做最小化敷衍交付，有的模型则习惯无休止地扩大搜索范围直到超时）的下限。

但它的核心矛盾在于：**它赚的是“当下模型短板”的快钱，却背着极高的跨代折旧率，并且在当下就要承受“提速与覆盖面”的直接冲突**。
一旦你用死板的工作流或过细的规则替模型做决定，虽然常见套路变快了，但只要现实问题稍微偏离预设（比如真实故障比报错时间晚了一秒、或者根因藏在既定分支之外），被捆住手脚的模型就会直接丢失细节甚至彻底卡死。更残酷的是，你是在和模型厂商的迭代速度赛跑——等三个月后下一代模型发布，它原本能自主探索搞定的事，反而被你写死的旧流程强行降智，你精心维护的脚手架瞬间从资产变成需要重构的负资产。

**第二类框：物理与系统边界（框住模型“怎么和现实世界交互”）**
既然“替模型思考”的框终将被淘汰，那什么才是不会被模型升级吞掉的真壁垒？答案是：**不管模型脑子里怎么想，只负责打通它与现实世界的感知通道、行动边界与客观反馈。**

在真实的垂直业务（比如工业现场诊断或复杂系统排障）里，很多人迷信“模型越强，只给一个 Bash 就够了”。但一旦落地就会撞上一堵冷酷的物理墙：诊断和决策的本质是**信息发现**。对于那 20% 真正棘手的疑难杂症，受限环境下的 Agent 往往不是体面地回答“我不知道”，而是直接给出看似合理实则错误的幻觉——因为**连判断“自己无法回答”这件事本身，也需要先发现足够的反面证据**。如果沙盒或简陋工具既挡住了危险操作、又斩断了信息发现的链路（比如看不到某次历史提交、访问不了某个内部几何校验端点），假设一条 10 步的取证链条里每一步拿到关键信息的概率在受限环境下掉到 95%，走完 10 步的成功率就会腰斩；哪怕一步降到 90%，端到端成功率就只剩三分之一。

因此，无论未来模型智商高到什么程度，下面这四件事模型厂商永远无法替你做，且模型越聪明，这层框的价值越成倍放大：

1. **信息发现通道与私有语境对齐**：再聪明的模型，也猜不到你业务里“口头俗称的某测试服”对应的是 K8s 还是 Docker、真实命名空间叫什么、或者日志里某个数字枚举 `3` 代表什么业务故障。如果把这些混乱的内部黑话直接做成参数晦涩的自定义工具，模型只会反复填错参数，甚至被迫退回 Bash 从零盲猜。打通真实数据源，抹平内部命名鸿沟，并用确定性脚本把上千行杂乱现场提炼成高信息密度的干净输入，是人的核心职责。
2. **控制流归模型，重活累活归确定性代码（确定性卸载）**：不要把**控制流（决定下一步查什么、怎么追查代码）**从模型手里夺走——只要需要自主顺藤摸瓜看代码，机械状态机就必然漏掉长尾真相。但同时，也不要让模型每次都在现场用 Bash 从零手搓几十行复杂脚本去捞日志、算几何或对齐生命周期。最理想的架构是**“极薄的自主循环（如 Pi SDK + Bash 兜底长尾灵活性）+ 经过真实轨迹清洗的轻量级确定性工具/CLI”**：先让模型用纯 Bash 跑通上百轮真实问题，看清它每次都在哪里重复造轮子或卡壳，再把那些确定性的高频重活（如跨服务追踪、精确数值计算、环境自动切换）提炼成语义极简的工具。如果一个自定义工具做得还不如模型现场手写 Python 好用，那它就毫无存在意义，甚至会成为干扰模型思考的负资产。
3. **高保真验证器与面向“结果”的评测闭环**：单机单 Agent 的“内循环”（Prompt + Bash + Edit）其实已经高度收敛，真正的瓶颈早就移到了环境与验收上。因为 Agent 是概率性系统，且每一步都是自主决策，企图“沿着中间步骤链条做机械验收”几乎是不可能的。在工程上，**端到端做对（正确性）永远远大于快与省**。谁能在具体业务里，构建出贴近真实物理现场的端到端结果验证器与回归基准（只核对最终是否抓出真根因、是否真正修好问题，并在保证结果正确的前提下再去优化轮次），谁就能把 AI 的试错闭环真正跑起来。
4. **权限隔离、爆炸半径与停止边界**：就算未来模型达到人类顶尖专家水平，你也不会给它生产环境的无审批写权限；就算给它只读调查权限，如果没有明确的超时熔断与“停止标准”，一个拼命想查出根因的模型也可能在几小时的历史日志里无限扩大时间片，把系统跑死。守住细粒度的权限护栏、控制试错的爆炸半径、定义清晰的交付与停止契约，是人类工程师永远无法卸下的责任。

### 3. 数学本质：外围工程不是在“摆弄曲线”，而是在做 AI 时代的 TCP 协议

回到机器学习视角，既然大厂给的 LLM 权重已经训练完冻住了（相当于函数曲线 $y = f(x)$ 已经固定），我们在外围折腾这些系统边界，是不是其实根本没有改变能力上限，只是在徒劳地摆弄曲线？

如果只做“单次问答（Chat）”，那确实被锁死在冻结的权重分布里。但 **Agent 系统的数学本质，早就不是对静态函数 $f(x)$ 做单次求值了**。哪怕不改模型里一个浮点权重，优秀的外围工程实际上在三个底层机制上实质性地突破了单点模型的上限：

- **第一，把“单次映射”变成了“推理期搜索”**：一旦在外围套上「生成候选 $\rightarrow$ 真实环境/验证器检验 $\rightarrow$ 报错反馈剪枝重试」的闭环，你运行的就不再是静态函数 $f(x)$，而是一个以 $f(x)$ 为启发式向导的搜索算法。一个单次通过率只有 20% 的模型，配合一个廉价且 100% 客观的验证器跑多轮闭环，端到端解决率可以轻松拉到 90% 以上。没有修改单步曲线，但用推理期算力与环境反馈，换出了单步曲线原本根本够不到的解。
- **第二，重塑输入坐标 $x$，把问题搬进曲线的“高保真区”**：大模型的冻结权重不是一条二维折线，而是一个极其庞大复杂的条件概率曲面 $P(y \mid x)$。在这个曲面上，有的区域先验极厚、回答极准，有的区域全是高熵幻觉。把充满内部歧义的参数表和 5 万行原始杂乱日志直接塞给模型，和先把环境映射关系理顺、提取出关键状态快照再塞给它，喂给模型的输入坐标 $x$ 完全不同。好的上下文工程与工具设计，本质上是在做**状态降噪与坐标变换**——强行把模糊混乱的现实问题，投射到模型概率曲面上最稳、最准的那块平地上。
- **第三，用系统级容错填平“单步高准确率”与“长链路崩溃”的鸿沟**：正如前面信息发现链条算过的那样，哪怕单步动作或取证的成功率高达 95%，无保护地连续自主走 10 步，端到端全对的概率也只剩下 $0.95^{10} \approx 59.8\%$；连续走 50 步，哪怕单步准确率 99%，成功率也只剩 $0.99^{50} \approx 60.5\%$——这在严肃工程里根本没法用。

外围的上下文降噪、环境对齐、分步验证、熔断控制与证据链留存，干的其实是计算机网络里 **TCP 协议**干的事：TCP 从来没有去修改底层网线或无线信道的物理误码率，但它在不可靠的物理层之上，通过校验、确认、重传和拥塞控制，把一个天生带概率抖动的信号通道，封装成了一个工程上绝对可靠的字节流。

## 六、脚踏实地的行动指南：以 Skill 与工具沉淀为例

明白了“哪些是终将淘汰的认知拐杖、哪些是越沉淀越值钱的物理边界”，具体到每天的实际工程中，我们到底该怎么管理手头的 AI、怎么对待越积越多的提示词、Skill 和自定义工具？

无论是个人使用支持自动沉淀经验的 Agent（不知不觉攒了一两百个 Skill，占掉系统提示词近 40% 的篇幅，近半数从不调用，高频调用的反而让模型钻牛角尖），还是在团队业务里给排障/研发 Agent 写各种领域规则与辅助插件，我们都会撞上同一个现实矛盾：

**每一个放进上下文的 Skill 或工具定义，实际上都是在强行修改模型当前会话的先验分布（注入人为归纳偏置）。它既可能在今天帮你省掉 20 轮盲目摸索，也可能在明天变成锁死模型智商的牢笼。**

### 1. 现实里的两难：为什么我们明知是“拐杖”，当下却还是得用？

如果我们站在纯粹的理论高地上说“凡是替模型思考的提示词和流程统统不许写”，那在今天的实际工程里是寸步难行的。

在真实的业务落地中，我们面对的是一个充满矛盾的现场：
- **不给拐杖，成本与耗时当场失控**：如果只扔给模型一个裸 Bash 和一句简陋的问题，哪怕是能力很强的模型，面对陌生的私有集群，也会花三四十轮调用去一点点摸索端口、试探命名空间、扩大时间窗口，甚至跑出耗时几分钟都停不下来的重查询；而换上另一个性格不同的模型底座，它又可能写个极简脚本随便捞两条表面日志，90 秒就给你交一份“体面但毫无用处的敷衍结论”。
- **给了拐杖，又会引发“教条主义”与“工具反噬”**：为了让它少走弯路，你自然会写一份详细的排障 Skill：告诉它先查什么、再查什么，并警告它“不要在反复调试抓取脚本上卡死”。结果它确实变快了（从 40 轮降到 10 轮），但副作用接踵而至——有的模型因为严格服从“不要反复调试脚本”的禁令，遇到稍微复杂一点的状态字段干脆放弃深挖，漏掉了真正的根因；有的模型被硬塞了一堆背景提示后，反而失去了停止感，在细枝末节上无限自我验证；更有甚者，你为了帮它省事而封装的自定义查询工具，只要时间窗口卡死了一秒，或者参数设计稍微绕一点，模型不仅查不到真相，还会连续七八次填错参数，效果反而不如直接放开让它用 Bash 现场写 Python 脚本。

到了**模型跨代升级**时，这种矛盾会进一步放大成“跨代污染”。就像 Anthropic 让不同模型玩 Minecraft 的实验所展示的：弱模型喜欢把记忆文件夹搞得无比庞大，事无巨细地记下每一步套路；而强模型原本只需要极少的锚点就能自由推进。当你换上新一代强模型，它看到旧时代留下的上百条 Skill 索引和死板 SOP 时，**不会自动忽略它们，反而会因为极强的指令遵循能力，把当年迁就弱模型的“保姆手册”当成不可违背的铁律去执行**——于是，当年的提效拐杖，直接变成了新模型的智商天花板。

### 2. 给 Skill 与工具做“折旧分级”：什么有当下收益但必被淘汰，什么能沉淀为真资产？

看清了“当下不得不用的现实收益”与“长期必然贬值的演化规律”，我们就不会再二极管式地全盘肯定或全盘否定 Skill，而是能拿出一把清晰的手术刀，对现有的任何一份 Skill 或工具库做**折旧分级**：

**第一类：高折旧的“战术补丁”（当下能救急提速，但注定随模型换代被淘汰）**
这类内容本质上是在替当前模型补齐规划、推理或表达短板。**你可以为了今天的交付效率写它，但心里必须清楚它是“耗材”而不是“资产”，绝不能让它无限膨胀、常驻全局：**
- **显式推理步骤与调查 SOP（Method）**：比如“四阶段排障法”、“必须先看 A 再看 B”、“先出骨架经人工确认才许写正文”。在当前模型经常漏查或一步写不对时，这套流程能显著托底下限、减少发散轮次；但它的副作用是限制搜索广度，且一旦下一代模型单步成功率跨过临界点，整套分步流程就会变成拖慢效率的累赘。
- **驯服特定“模型脾气”的修辞与策略补丁**：为了治某款模型“爱偷懒敷衍”而写的强制深挖指令，或为了治另一款模型“无限发散超时”而写的收敛警告，以及各种去 AI 味、角色扮演的文风控制。这些全是在和特定模型快照的性格博弈，大模型三个月换一代，这批提示词就得全部重调甚至直接作废。
- **公共领域常识与低收益捷径**：行业通用概念、标准命令的 `--help` 用法，或者读一遍要花 2000 tokens 却仅仅帮模型省掉两次 `ls` 试探的啰嗦指南。模型自带或现场试一下更快，写死在文档里纯属浪费注意力预算。

**第二类：零折旧的“战略基建”（任何智力的模型都无法凭空猜出，且随模型变强反而升值）**
真正值得花心血长期打磨、沉淀进团队核心库的，只有下面这四样东西——它们不教模型怎么思考，只给模型装**“眼睛”（私有信息通道）**和**“刹车”（物理边界与停止契约）**：
1. **不可观测的私有事实与命名映射（Private Facts）**：模型再聪明，也绝对推算不出你私有世界里的约定——比如业务口中的“某测试服”到底对应哪个 K8s 命名空间和哪台机器、权威代码副本在哪个路径、日志里某个枚举值 `3` 代表什么真实物理状态、某个历史方案当初为什么被否决。把这些“内部黑话与真实物理拓扑的映射表”写清楚，是消灭无谓盲搜最有效的一招。
2. **高代价踩坑换来的“负知识”（Negative Knowledge）**：不是通用的编程常识，而是必须花真金白银、漫长等待或真实故障才能撞出来的环境暗礁——比如“线上某张表不带时间索引直接查会卡死 5 分钟”、“某个接口并发高了会静默封号”、“某条同步命令带特定参数会静默丢数据”。智力替代不了物理碰壁，但这类记录必须标注验证日期（`verified_at`），随外部系统演进及时清理。
3. **物理权限边界与安全护栏（Boundaries）**：允许读写哪些目录、哪些生产操作绝对禁止、哪些外部动作必须先停下来让人确认、数据能不能出内网。**这是唯一随模型变强而反向升值的东西**——模型自主写代码、调工具的能力越强，跑得越远，爆炸半径就越大，清晰的护栏就越值钱。
4. **验收标准与“停止契约”（Contract & Stopping Criteria）**：不规定模型“中间每一步必须怎么查”，但明确规定**“查到什么程度算真正回答了问题（如必须定位到封路或车辆缓刹等物理根因，绝不能停在‘路由未下发’这种表面现象）”、“什么情况下必须停止扩窗并如实报告证据不足”**，以及你与模型默认输出习惯的最小分歧点。把过程放开，把终点和停止线卡死。

### 3. 日常管理 AI 的实操原则

既然我们的库里同时混杂着“当下救急的战术拐杖”和“长期保值的战略基建”，日常管理就不应该再去搞一套繁琐的“定期全量审计脚本”（那又是人在替弱模型整理文件夹），而是直接建立一套抗老化的工程习惯：

1. **根据真实运行轨迹，决定抽什么 Skill 或 Tool（拒绝凭空设计）**：
   不要一上来就凭想象力给 Agent 写几十条死板规则或封装一堆参数复杂的工具，无论是垂类 Agent 还是个人 Agent。让它在真实问题上跑上几十到上百轮。观察它的真实轨迹：它每次都在哪里白白浪费 10 轮去试探环境？那就把那条私有环境映射补进文档。甚至可以要求回顾曾经 3 个月的卡点，哪里经常卡住，就改哪里。
2. **把省下来的精力，投向“信息通道与结果验证器”**：
   停止在提示词字眼上和模型的思考方式反复拉锯。当你发现 Agent 表现不稳定、时好时坏或者回答肤浅时，先按第四、第五章的逻辑去排查物理链路：是不是内部环境的命名太混乱导致它连入口都找错了？是不是自定义工具卡死了时间窗口反而遮蔽了 1 秒之差的关键日志？是不是缺少一个能模拟真实故障（比如故意把目标点设进封路区、故意报错车号）来自动检验它能否挖出真根因的端到端测评集？

**总结全文：**
从最早的线性模型、决策树，到今天的千亿参数大模型与 Agent，机器学习的底层铁律从未改变——**模型永远只能在给定的先验偏置下，去拟合输入特征所包含的信息，并依赖外部验证器的反馈来突破单步猜想的上限。**

在模型权重被大厂冻结的今天，我们在外围做工程、写 Skill、管 Agent，本质上是在做一场动态的平衡：我们既要务实地承认“认知拐杖”在当下模型身上的提效收益，敢于在必要时用它托底；又要保持清醒的架构克制，绝不把拐杖当成护城河。随着模型一路变强，主动折断那些替模型代劳思考的旧拐杖，把控制流交还给模型，把确定性的重活沉淀为干净的工具，守住私有世界的事实通道、安全边界与真实结果验证器——人越是不去越俎代庖地干预模型“怎么想”，系统就越简单，模型反而能在我们划定的可靠轨道上跑得越远。
